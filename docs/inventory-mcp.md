# Opt-in inventory MCP server

This server is **not** an LLM-selected diagnostic tool. It is intended for
a trusted verification service, using an operator-controlled inventory snapshot.
No inventory data is generated by the application.

Create a JSON snapshot from your actual CMDB, service catalog, or other
authoritative source (example below is **schema only**, not real inventory):

```json
{"entities":[{"entity_id":"<actual-id>","kind":"<actual-kind>"}]}
```

Set `INVENTORY_FILE` to its absolute path and run
`python -m app.mcp_servers.inventory`. The server listens on localhost:8104.

A missing file, invalid JSON, duplicate entity IDs, or malformed record
causes verification to fail closed. This does not authenticate the source
or protect against a compromised inventory file; production deployment
requires filesystem access controls, source provenance, audit logging,
and connector identity. The server is deliberately not added to
`create_mcp_client()` because that client exposes tools to the LLM and
currently validates evidence by incident_id. A dedicated trusted MCP
client and verified graph ingestion wiring are still required.
